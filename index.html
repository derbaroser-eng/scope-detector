The problem

Scope creep is silent until it is too late.

Project management tools track tasks and time but don't compare current work against the original contract scope. Someone has to notice — and by then, the margin is gone.

Manual scope tracking is inconsistent and reactive.

One person reviews scope weekly. Another doesn't review at all. The same out-of-scope work gets approved on one project and rejected on another.

What it does

Feed it a project's contract scope and current work items. Get back:

in_scope

Work items that match the contract.

out_of_scope

Work items that don't match the contract.

scope_creep_detected

True if any work item is out of scope.

How it works

$ echo '{"contract_scope":["Design website homepage","Implement contact form"],"current_work":["Design website homepage","Add blog section"]}' | python detect.py
{"in_scope": ["Design website homepage"], "out_of_scope": ["Add blog section"], "scope_creep_detected": true}

Deterministic substring matching. No model, no API call, no data leaves your machine. Same input to same output, every time.

Why deterministic

An LLM deciding what is in scope is a black box you cannot audit.

When a detector says "this is out of scope", you need to know why. A rule you can read is a rule you can trust, debug, and improve.
